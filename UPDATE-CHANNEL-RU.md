# Автообновление VANTA Launcher · Pre-Release

В версии 1.3.0-beta.2 поддерживаются GitHub Releases (рекомендуется) и собственный HTTPS-каталог. Важное отличие: при публикации через `PUBLISH-GITHUB.bat` адрес публичного репозитория записывается electron-builder в `resources/app-update.yml` внутри установщика. Поэтому после первой ручной установки beta.2 клиент сам знает, откуда получать будущие обновления — пользователю не требуется вручную вводить адрес канала.

## Вариант A — GitHub Releases (рекомендуется)

1. Создай **публичный** GitHub-репозиторий для VANTA Launcher.
2. Открой папку исходников VANTA и запусти `PUBLISH-GITHUB.bat` двойным щелчком. BAT-файл запускает PowerShell-скрипт с `-ExecutionPolicy Bypass` только для этого процесса; системная политика Windows не меняется.
3. Введи адрес репозитория в формате `owner/repository`.
4. Скрипт попросит fine-grained GitHub token. Создай токен только для этого репозитория с разрешением **Contents: Read and write**. Ввод скрыт; токен используется только в текущем процессе, не сохраняется в файлы и не включается в приложение. Не отправляй токен никому.
5. Скрипт соберёт Windows x64 NSIS, укажет `channel: beta` и `releaseType: prerelease`, встроит конфигурацию GitHub в `app-update.yml` и опубликует Pre-Release вместе с update metadata и установщиком.
6. Установи созданный beta.2 Setup вручную один раз. Этот выпуск уже знает репозиторий и сможет получать последующие обновления автоматически.
7. Для каждого будущего релиза увеличивай `version` в `package.json` (например, `1.3.0-beta.3`), обновляй `RELEASE_NOTES.md` в корне проекта и снова запускай `PUBLISH-GITHUB.bat`.

Репозиторий должен оставаться публичным для клиентов лаунчера. Не создавай draft-релиз: electron-updater не видит draft GitHub Releases. Выпуск должен содержать channel metadata `beta.yml` (или fallback metadata, созданную electron-builder) и `Vanta-Launcher-Setup-*.exe`. Файлы metadata и установщик должны относиться к одной и той же сборке.

## Вариант B — собственный HTTPS feed

1. Размести статический каталог с TLS/HTTPS.
2. В корне каталога должны находиться `beta.yml`, установщик и соответствующий `.blockmap`.
3. Собирай update metadata командой electron-builder с `--publish always`, затем загружай manifest и артефакты из одной сборки в каталог.
4. В VANTA открой «Для разработчика» → «Подключение автообновлений», выбери «Собственный HTTPS release feed», введи каталог, проверь соединение и сохрани.

`beta.yml` должен содержать корректные `version`, `path` (или `files[].url`) и `sha512`. Используется канал `beta`.

## Как работает клиент

- В сборках, выпущенных `PUBLISH-GITHUB.bat`, репозиторий читается из встроенного `resources/app-update.yml`.
- Сохранённый override из `%APPDATA%\nebula-launcher\Nebula Launcher\NebulaLauncher\update-feed.json` имеет приоритет над встроенным адресом.
- Канал проверяется автоматически при старте установленного приложения и затем каждые 10 минут.
- Кнопка «ПРОВЕРИТЬ» выполняет ручную проверку. При доступной версии появляется кнопка скачивания, затем перезапуск для установки.
- Проверка в панели разработчика проверяет доступность источника; публикация новой версии всё равно требует сборки и размещения release assets.
- Изменения в исходном коде ChatGPT не попадают на компьютеры автоматически. Для доставки каждого изменения нужно создать новую версию и опубликовать её в подключённом репозитории.

## Безопасность

Используй только HTTPS. Публичный репозиторий не требует токена на компьютерах пользователей. Токен публикации нужен только разработчику во время выпуска; не храни его в `package.json`, `.env`, исходниках или в собранном приложении. Не вставляй токены в чат.


## Заметки релиза

`PUBLISH-GITHUB.bat` после публикации установщика обновляет тело GitHub Release содержимым корневого `RELEASE_NOTES.md`. Electron Updater получает этот текст в `info.releaseNotes`, а интерфейс показывает его в баннере и карточке обновления. Перед следующим выпуском обязательно увеличь `version` в `package.json` и обнови `RELEASE_NOTES.md`.
